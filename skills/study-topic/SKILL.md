# Study topic

実行前に [Skill setup](../../docs/workflow.md#skill-setup) を読み、利用環境に合わせて実行手段と依存機能を確認する。

トピックを能力単位の学習経路へ分解し、永続する学習マップを状態として一要素ずつ進める。

## 原則

- 単位を資料の章ではなく、説明・判断・実行できる能力にする
- 各要素に前提、一次資料、小さな実習、観測可能な完了条件を持たせる
- 一度に扱うのは一要素だけにする。必要な前提以外へ話を広げない
- 説明を読んだだけで学習済みにせず、ユーザ自身の説明・判断または実習結果で確認する
- マップは進捗と経路の正本であり、学習内容の本文を複製しない
- 公式文書、原論文、正本コードなどの一次資料を優先し、取得日やversionを残す
- APIや実装が変わり得るトピックでは、学習時に資料の現行性を再確認する
- 単一書籍を順に学ぶ場合は `study-book` へ渡す

## 初回: 学習マップを作る

1. トピック、到達したい能力、現在地、利用可能な環境を確認する。欠けた情報で経路が変わる場合は、調査やマップ提示へ進まず一問ずつ聞く
2. 連合検索で既存記事・関連knowledgeを確認し、検索対象外の学習マップはUIツリーまたは`articles/studies/`で確認する
3. 学習方針と調査計画をまとめて承認してもらい、`survey` で現在の一次資料、前提関係、代表的な実習経路を調べる。内部利用なので記事draftは作らない
4. 最短の到達経路を能力単位へ分解する。共通の基礎を先に置き、高度な枝は再開条件つきで後段へ置く。複数の実装経路があり選定根拠がまだない場合は一つへ決め打ちせず、必要な基礎を学んだ後の比較・判断を一要素として置く
5. 全要素をまとめて提示し、順序、粒度、既知要素、完了条件をユーザと直す
6. 承認後、`articles/studies/<topic-slug>.md` にマップを作り、別コミットする。既存マップはUIツリーまたは`articles/studies/`から辿り、一覧への追記は行わない

マップは次の情報だけを持つ。

```markdown
---
topic: "対象トピック"
goal: "最終的に観測できる能力"
baseline: "開始時点の現在地"
started: YYYY-MM-DD
sources_checked: YYYY-MM-DD
---

# 学習マップ — 対象トピック

## 到達点

## 学習経路

### 段階名

- [ ] 要素名 — できるようになること
  - 前提: なし、または先行要素
  - 一次資料: URL、文書、code path
  - 実習: 最小の手を動かす課題
  - 完了条件: 説明・判断・実行で観測する条件
```

状態は未着手・既知・学習済みの3つにする。初回マップ作成では本文理解や記事draftを作らない。学習中に要素の分割・統合・順序変更が必要になったら、理由を示してユーザ確認後にマップへ反映する。

## 継続: 一要素を学ぶ

1. マップから前提を満たした次の未着手要素を提案する。ユーザ指定を優先し、未消化の前提があれば明示する
2. 今回の問い、実習、完了条件を短く再掲する
3. 指定済みの一次資料だけを読むなら `summarize-source` を内部利用する。複数資料の探索、現行仕様の確認、コード調査、実測が必要なら `survey` を内部利用する。いずれも独自の記事draftは作らせない
4. 最小のメンタルモデルから説明し、IR・コード・数式・実行結果など対象に合う具体物へ接続する
5. 実習を一緒に行う。環境がない場合は、読解、変換予測、設計判断など同じ能力を観測できる代替課題を使う
6. 一問ずつ確認し、ユーザが自分の言葉で説明するか、完了条件を満たす成果を確認する。誤解があれば同じ要素の中で例を変えて続ける
7. 独立して再読する価値のある理解ができた場合だけ `write-article` へ渡す。単なる導入や実習なら記事を強制しない
8. 記事の判定と要素の最終判定を待つ。学習マップは判定前に完了へ変えない

## 判定と更新

- 学習済み: 完了条件を満たした根拠、日付、記事・実習artifact・参照sourceへのリンクを残し、マップ更新を別コミットする
- 既知: 確認できた能力と日付を残し、マップ更新を別コミットする
- 記事をストック: 記事コミット後に、学習済みと記事リンクをマップへ別コミットする
- 記事を却下: 学習済みにできるなら、記事なしの理由を添えてマップを更新する
- 保留または理解未達: マップを完了へ変えず、同じ要素から再開する。未判定draftや実習artifactは残す

記事ストック、恒久knowledgeへの蒸留、学習マップ更新を同じコミットに混ぜない。全要素が完了したら、最終到達点を小さな統合課題で確認してからマップを完了扱いにする。
