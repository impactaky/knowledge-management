# Grill, federated

Read [Skill setup](../../docs/workflow.md#skill-setup) before starting to resolve
the environment's execution methods and required capabilities.

Read the explicitly selected Catalog through an available adapter or directly at
its verified location. Missing selection is a configuration problem; never guess
a store. Read explicit file entrances and required references. Select relevant
files within directory entrances; an INDEX is not implicitly required.

Clarify purpose, applicability, evidence, completion criteria and unresolved
choices. Investigate discoverable facts yourself. Ask questions only when answers
will change the work; keep dependent questions until their prerequisites are
settled. Offer a concrete interpretation and test it against examples and
counterexamples. Preserve the caller's one-question-at-a-time and approval rules.
Carry prior approvals forward. For direct design work, obtain agreement on the
shared understanding before implementation.

Compare terms with the existing glossary and resolve conflicts explicitly.
Record adopted terms as **Term** followed by a concise definition and scope in
CONTEXT.md. Record consequential decisions with context, decision, alternatives
and consequences in the existing decisions directory. These generic formats
make external grilling/domain-modeling skills optional; they are not vendored.

Route knowledge to the narrowest applicable package and correct trust boundary.
Repository-specific knowledge stays with that repository; shared definitions
have one canonical location and references elsewhere. Moving a definition does
not broaden its applicability. Update the Catalog or optional INDEX only when
reading conditions or navigation to rules change, not for every new document.

Use [knowledge changes](../../foundation/docs/knowledge-changes.md) for coherent
references and commit boundaries. Do not force this interview into a complete
`summarize-source` input or an ordinary article review.
