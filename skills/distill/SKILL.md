# Distill

実行前に [Skill setup](../../docs/workflow.md#skill-setup) を読み、利用環境に合わせて実行手段と依存機能を確認する。

ソース要約・調査・聞き取り・記事・実装セッションから、今後従うべき知識だけを蒸留層へ著述する。`grill-federated` と並ぶ、蒸留層への正規の書き込み入口。

## 手順

1. 連合カタログを読み、関連パッケージの指定file/directory入口から必要な正本を読む。Anchorと必読条件に従い、directoryにINDEXがあっても自動的に必読にはしない
2. セッションから恒久的な事実・用語・判断・規則を列挙する
3. 連合検索で既存知識と重複・矛盾しないか確認する。採用する判断と既存Article・Claim Lineに食い違いが見つかったら、根拠と修正案を示して変更内容を議論し、合意後に`write-article`の差し替えとして別コミットで反映する
4. 適用範囲が最も狭いパッケージを選ぶ。迷ったら狭い方へ置く
5. 用語はCONTEXT、覆すコストの高い判断はADR、実践規則は既存の適切なファイルへ著述する
6. 読む条件や案内すべき規則が変わったときはCatalogまたは既存の任意INDEXを更新し、必要なら共有repoのミラーを同期する。文書追加ごとの一覧追記は不要
7. [知識の更新規約](../../foundation/docs/knowledge-changes.md)に従い、適用条件・信頼境界・正本一箇所・参照の整合性を検査してから、蒸留変更だけをコミットする。Promotionは保存先の移動と適用範囲の拡大を区別する

## 残さないもの

- 一時的なタスク状態
- ソースや会話の要約
- 記事本文の複製
- 既に正本へ記録済みの事実
- 採用していない外部主張
- 機密・トークン類

何もなければ無理に作らない。報告では蒸留した事実と書き先、あえて残さなかったものを短く示す。外部へのpushはユーザが別途求めた場合だけ行う。
